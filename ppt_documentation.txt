================================================================================
PROJECT PRESENTATION NOTES
TITLE: AI-Powered Email Threat Detection, Geolocation & Forensic Intelligence Platform
================================================================================

--------------------------------------------------------------------------------
SLIDE 1: TITLE
--------------------------------------------------------------------------------
• Title: AI-Powered Email Threat Detection, Geolocation & Forensic Intelligence Platform
• Subtitle: Email forensic investigation, suspicious route analysis, and threat intelligence
• Audience: Security analysts, investigators, technical teams, and stakeholders

--------------------------------------------------------------------------------
SLIDE 2: PROBLEM
--------------------------------------------------------------------------------
• Phishing and malicious email campaigns remain one of the most common attack vectors.
• Attackers spoof identities, manipulate headers, hide destinations behind short links, and route mail through untrusted infrastructure.
• Analysts struggle to combine evidence from headers, route metadata, domains, URLs, and threat feeds in one workflow.

--------------------------------------------------------------------------------
SLIDE 3: SOLUTION
--------------------------------------------------------------------------------
• Upload a raw `.eml` file to a web platform.
• Parse the message and reconstruct the forensic picture.
• Detect impersonation, protocol issues, suspicious routing, risky links, and malicious infrastructure.
• Score the threat and highlight why the message is suspicious.

--------------------------------------------------------------------------------
SLIDE 4: SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------
• Frontend: Next.js dashboard with report cards, risk score, route map and threat graph
• Backend: Express + TypeScript API for analysis orchestration
• Database: PostgreSQL + Prisma for storing email cases and investigations
• Analysis services: headers, routes, domains, URLs, geolocation, threat intel, NLP heuristics

--------------------------------------------------------------------------------
SLIDE 5: CORE FEATURES
--------------------------------------------------------------------------------
• `.eml` file intake and MIME parsing
• Header anomaly review: Reply-To, Return-Path, Message-ID
• SPF / DKIM / DMARC audit
• Domain impersonation and typosquatting checks
• URL extraction and suspicious link scoring
• SMTP `Received:` chain parsing and origin IP detection
• Geolocation and route mapping
• Risk scoring and severity classification
• Threat Intel correlation and dashboard reporting

--------------------------------------------------------------------------------
SLIDE 6: TECHNOLOGY STACK
--------------------------------------------------------------------------------
• Frontend: Next.js, React, TypeScript, Tailwind CSS, Leaflet
• Backend: Node.js, Express, TypeScript
• Database: PostgreSQL, Prisma
• Parsing: `mailparser`, `multer`
• Threat analysis: custom rule engine and external intelligence checks

--------------------------------------------------------------------------------
SLIDE 7: KEY FORENSIC SIGNALS
--------------------------------------------------------------------------------
• Mismatch between displayed sender and actual reply destination
• Missing or malformed Message-ID headers
• Failed authentication checks across SPF, DKIM, and DMARC
• Lookalike domains, freemail identities, or abusive brand impersonation
• Redirects via URL shorteners or raw IP URLs
• Mail routing that indicates suspicious or foreign infrastructure
• High-risk combined indicators leading to a strong risk score

--------------------------------------------------------------------------------
SLIDE 8: ANALYSIS FLOW
--------------------------------------------------------------------------------
1. User uploads suspicious email file
2. Backend parses message structure and metadata
3. Forensic services inspect headers, domains, URLs, and route chain
4. Threat intelligence and geolocation services enrich the evidence
5. Risk engine calculates the aggregate threat score
6. Frontend renders the forensic dashboard and printable report

--------------------------------------------------------------------------------

SLIDE 12: CLOSING
--------------------------------------------------------------------------------
• This project blends email forensics, threat intelligence, route analysis, and risk scoring into a single operational workflow.
• The architecture is intentionally modular so it can evolve into more advanced AI and correlation models without changing the core investigation flow.

• Status: Roadmap
• Plan / Objective:
  - Turn the tool into an enterprise-grade Digital Forensics Incident Response (DFIR) case system.
• What Will Be Done:
  - Phase 15: Case management dashboard (Case IDs, analyst notes, severity tagging, evidence attachment).
  - Phase 16: Cryptographic evidence integrity (SHA-256 file hashing, tamper logs, strict chain of custody, privacy masking).
• Value:
  - Ensures forensic evidence collected is legally defensible and adheres to chain-of-custody standards.
